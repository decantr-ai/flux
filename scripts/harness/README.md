# Synthetic Flux harness

Run `node scripts/harness/run.mjs --out /private/tmp/flux-lab-unique` from the repository. The output path must not exist. The harness creates a marker, copies source, docs, package metadata and built assets to `baseline/`, records a SHA-256 file manifest and git HEAD/status/diff fingerprint in `baseline.json`, and builds immutable `cases.json` from the copied production modules. The installed `node_modules` is linked, not copied; its contents are not independently frozen. No live `.flux`, auth data or unrelated chats are read. Run outputs and any lab changes stay inside the marked temporary directory.

`mechanics.json` records every check, counts, and the exit policy. Exit 1 means at least one automated gate failed; exit 2 means an automated check was blocked by the environment and no gate failed; exit 0 means no automated failure or environmental blocker. Failures take precedence when both occur. Explicitly pending manual checks remain visible and do not count as passes or change the exit code. A loopback bind permission or address error is recorded as environment-blocked rather than a product defect. Run the live lab with `node scripts/harness/serve-lab.mjs --workspace /private/tmp/flux-lab-unique`; it serves copied React assets and the copied backend on a random loopback port. `lab.json` gives the URL and synthetic data directory. Queue calls go only to `queue-deliveries.jsonl`; Finder calls go only to `finder-spy.jsonl`. `queue-state.json` supports `accepted`, `fail`, or `delayed` modes. No real chat can be sent a message.

Use `node scripts/harness/control.mjs --workspace /private/tmp/flux-lab-unique --op OP`, where OP is `passive`, `semantic`, `new-checkpoint`, `result`, `reopen`, `queue-fail`, or `queue-accept`. For recovery tests, `legacy-feedback` adds a synthetic legacy preview; `remove-check` backs up the lab journal then removes only its synthetic check record; `confirm-receipt --request-id ID` and `confirm-feedback-receipt --request-id ID` append simulated late receipts for failed synthetic requests. Controls require the marker and matching lab metadata; `result` attaches a bounded fixture answer to the most recent queued synthetic diagnostic. Run a fresh output for independent trials. The prompts contain fixture evidence and production instructions; expected facts and grading guidance are separate in `cases.json`. The generated packets should be treated as immutable.
